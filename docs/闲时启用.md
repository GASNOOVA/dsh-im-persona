# 闲时启用（节省 DeepSeek API 成本）

> 全局开关：开启后，微信与 QQ 机器人**只在 DeepSeek API 非高峰时段响应消息**；高峰时段收到的消息被静默丢弃，不调用模型、不产生回复，以节省费用。默认关闭。

## 1. 为什么需要

DeepSeek API 在**北京时间 00:30–08:30**（UTC 16:30–次日 00:30）提供优惠计费，其余时间（UTC 00:30–16:30）为高峰时段。个人使用的机器人并不需要 7×24 小时响应：夜间和白天高峰期的自动回复既费 token，也通常无人查看。开启「闲时启用」后：

- 非高峰时段：机器人照常响应；
- 高峰时段：入站消息直接丢弃，**不进入 Harness、不建会话、不回复、不消耗 token**；
- 平台连接与消息轮询保持正常，非高峰开始后立即恢复响应；
- 不会积压消息：被丢弃的消息不会在非高峰时补发（它们已随更新游标消费）。

## 2. 时段定义

| 名称 | UTC | 北京时间 |
| --- | --- | --- |
| 非高峰（响应） | 16:30 – 次日 00:30 | 00:30 – 08:30 |
| 高峰（静默） | 00:30 – 16:30 | 08:30 – 次日 00:30 |

判断固定按 UTC 分钟计算，与宿主时区、夏令时无关。实现见 `src/channels/shared/off-peak.mjs` 的 `DEEPSEEK_OFF_PEAK_WINDOW` 与 `isOffPeakAt()`。

## 3. 使用方法

1. 打开「设置 → IM机器人（个人版）→ 通用」；
2. 在「闲时启用」一行打开开关；
3. 开关下方会显示当前状态：
   - **已开启，当前为非高峰时段，机器人正常响应。**
   - **已开启，当前为高峰时段，入站消息将被静默丢弃，以节省 API 费用。**
   - **已关闭，机器人始终响应消息。**

开关保存后**立即生效**，无需重启 DSH。微信与 QQ 共用同一个开关。

也可以直接调用管理 RPC（与设置页等价）：

```json
// settings.off-peak.get  → 读取
{ "ok": true, "value": { "enabled": true, "offPeakNow": false, "activeNow": false,
  "schedule": { "utcStart": "16:30", "utcEnd": "00:30",
                "beijingStart": "00:30", "beijingEnd": "08:30" } } }

// settings.off-peak.set  → 保存
{ "enabled": true }
```

两个端点挂在现有 `/dsh-im-settings` 复合管理通道上（`plugin-src/host/off-peak-rpc.mjs`），鉴权沿用该通道的 `rpcAuthority`。

## 4. 行为细节

- **入站门控**：微信在 `WeixinRuntime.#runMonitor` 调用 `bridge.accept()` 之前判断；QQ 在 `QqRuntime` 的 `message` 事件处理器与 typing predicate 中判断。命中高峰且开关开启时整条消息丢弃，并写一条 info 日志。
- **不回复、不建会话**：消息不会到达 Harness，因此不会出现「正在输入」、不会产生会话记录、也不会触发访问策略/命令处理。
- **轮询继续**：微信继续 `getUpdates` 并推进 `get_updates_buf`；QQ 保持 WebSocket 连接与订阅。非高峰恢复后无需重连。
- **只影响新的入站消息**：已经在执行中的任务、由主动投递或延迟交付触发的请求不受影响；计划任务在高峰期运行仍会调用 API。
- **故障放行（fail-open）**：设置文件缺失或损坏时按「关闭」处理；运行时判断失败也按「不拦截」处理，宁可多花一点费用，也不让机器人无提示地永久静默。
- **状态持久化**：`$DSH_HOME/integrations/dsh-im/off-peak-settings.json`，文档格式 `{ "version": 1, "offPeak": { "enabled": true } }`，原子写入。删除该文件等价于关闭。

## 7. 已知限制

- 时段目前**固定**为 DeepSeek 官方优惠时段，不提供自定义窗口；如官方调整计费时段，需要改 `DEEPSEEK_OFF_PEAK_WINDOW` 并重新构建。
- 高峰时段被丢弃的消息不会提示发送者（这正是「静默」的预期），也不会补发；重要消息请避开高峰或关闭开关。
- 该开关只拦截入站消息，不暂停计划任务、进行中的任务或主动投递。
