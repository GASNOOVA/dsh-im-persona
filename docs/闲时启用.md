# 闲时启用（节省 DeepSeek API 成本）

> 全局开关：开启后，微信与 QQ 机器人**只在 DeepSeek API 空闲时段响应消息**；高峰时段收到的消息被静默丢弃，不调用模型、不产生回复。空闲时段价格为高峰时段的一半。默认关闭。

## 1. 为什么需要

DeepSeek API 对工作日高峰时段按全价计费，其余时间（包括周末与法定节假日）按半价计费。个人使用的机器人并不需要 7×24 小时响应：夜间和高峰期的自动回复既费 token，也通常无人查看。开启「闲时启用」后：

- 空闲时段：机器人照常响应，API 按半价计费；
- 高峰时段：入站消息直接丢弃，**不进入 Harness、不建会话、不回复、不消耗 token**；
- 平台连接与消息轮询保持正常，进入空闲时段的边界后立即恢复响应；
- 不会积压消息：被丢弃的消息不会在空闲时段补发（它们已随更新游标消费）。

## 2. 时段定义（DeepSeek 官方规则）

DeepSeek 官方定义：**北京时间周一至周五（不含中国法定节假日）09:00–12:00、14:00–18:00 为高峰时段**；其余时段均为空闲时段，价格为高峰时段的一半。

| 名称 | 北京时间（UTC+8） |
| --- | --- |
| 高峰（静默） | 周一至周五 09:00–12:00、14:00–18:00，法定节假日除外 |
| 空闲（响应） | 工作日其余时间（00:00–09:00、12:00–14:00、18:00–24:00） |
| 空闲（响应） | 周六、周日全天 |
| 空闲（响应） | 中国法定节假日全天（含调休放假日期） |

补充规则（DeepSeek 官方 2026-09-19 说明）：**调休上班的周末也按周末计费**，即全天按空闲时段；因此周六、周日无论是否调休上班都全天空闲，不需要单独维护。

判断统一换算为北京时间（UTC+8）后计算，不受宿主时区或夏令时影响。实现见 `src/channels/shared/off-peak.mjs` 的 `DEEPSEEK_PEAK_WINDOWS`、`isPeakAt()`、`isOffPeakAt()`。

### 内置法定节假日表

- **2026 年**（国办发明电〔2025〕7号）：元旦 1/1–1/3；春节 2/15–2/23；清明 4/4–4/6；劳动节 5/1–5/5；端午 6/19–6/21；中秋 9/25–9/27；国庆 10/1–10/7。
- **2027 年**（国办发明电〔2026〕10号）：元旦 1/1–1/3；春节 2/5–2/13；清明 4/3–4/5；劳动节 5/1–5/5；端午 6/9；中秋 9/15；国庆 10/1–10/7。

后续年份或临时假期可在设置页「额外节假日」文本框补充（每行一个 `YYYY-MM-DD`），或直接修改设置文件的 `extraHolidays` 数组。

## 3. 使用方法

1. 打开「设置 → IM机器人（个人版）→ 通用」；
2. 在「闲时启用」一行打开开关；
3. 开关下方会显示当前状态与时段说明：
   - **已开启，当前为空闲时段（半价），机器人正常响应。**
   - **已开启，当前为高峰时段，入站消息将被静默丢弃，以节省 API 费用。**
   - **已关闭，机器人始终响应消息。**
4. 需要补充节假日时，在「额外节假日」文本框按 `YYYY-MM-DD` 每行一个填写，点击「保存节假日」。

开关保存后**立即生效**，无需重启 DSH。微信与 QQ 共用同一个开关。

也可以直接调用管理 RPC（与设置页等价）：

```json
// settings.off-peak.get  → 读取
{ "ok": true, "value": { "enabled": true, "offPeakNow": false, "activeNow": false,
  "schedule": {
    "timezone": "Asia/Shanghai (UTC+8)",
    "peakWindows": [ { "start": "09:00", "end": "12:00" },
                     { "start": "14:00", "end": "18:00" } ],
    "weekdays": "周一至周五",
    "weekendOffPeak": true,
    "holidaysOffPeak": true,
    "holidayDates": ["2026-10-01", "..."],
    "extraHolidays": ["2028-01-01"]
  } } }

// settings.off-peak.set  → 保存（extraHolidays 省略时保留原值）
{ "enabled": true, "extraHolidays": ["2028-01-01"] }
```

两个端点挂在现有 `/dsh-im-settings` 复合管理通道上（`plugin-src/host/off-peak-rpc.mjs`），鉴权沿用该通道的 `rpcAuthority`。

## 4. 行为细节

- **入站门控**：微信在 `WeixinRuntime.#runMonitor` 调用 `bridge.accept()` 之前判断；QQ 在 `QqRuntime` 的 `message` 事件处理器与 typing predicate 中判断。命中高峰且开关开启时整条消息丢弃，并写一条 info 日志。
- **不回复、不建会话**：消息不会到达 Harness，因此不会出现「正在输入」、不会产生会话记录、也不会触发访问策略/命令处理。
- **轮询继续**：微信继续 `getUpdates` 并推进 `get_updates_buf`；QQ 保持 WebSocket 连接与订阅。进入空闲时段后无需重连。
- **只影响新的入站消息**：已经在执行中的任务、由主动投递或延迟交付触发的请求不受影响；计划任务在高峰期运行仍会调用 API。
- **故障放行（fail-open）**：设置文件缺失或损坏时按「关闭」处理；运行时判断失败也按「不拦截」处理，宁可多花一点费用，也不让机器人无提示地永久静默。
- **状态持久化**：`$DSH_HOME/integrations/dsh-im/off-peak-settings.json`，文档格式 `{ "version": 1, "offPeak": { "enabled": true, "extraHolidays": [] } }`，原子写入。删除该文件等价于关闭。

## 7. 已知限制

- 高峰窗口固定为 DeepSeek 官方定义，不提供自定义窗口；如官方调整计费规则，需要修改 `DEEPSEEK_PEAK_WINDOWS`。
- 内置节假日表覆盖 2026、2027 年；之后年份的法定节假日需通过「额外节假日」补充（或更新内置表后重新构建），否则只按周末规则判断。
- 高峰时段被丢弃的消息不会提示发送者（这正是「静默」的预期），也不会补发；重要消息请避开高峰或关闭开关。
- 该开关只拦截入站消息，不暂停计划任务、进行中的任务或主动投递。
