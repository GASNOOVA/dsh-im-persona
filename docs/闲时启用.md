# 闲时启用（节省 DeepSeek API 成本）

> 全局开关：开启后，微信与 QQ 机器人**只在 DeepSeek API 空闲时段调用模型**；高峰时段不调用模型、不建会话，只自动回复一条固定提示（「大肥鱼正在睡觉中…」），同一聊天 5 分钟内最多一次。空闲时段价格为高峰时段的一半。默认关闭。

## 1. 为什么需要

DeepSeek API 对工作日高峰时段按全价计费，其余时间（包括周末与法定节假日）按半价计费。个人使用的机器人并不需要 7×24 小时响应：夜间和高峰期的自动回复既费 token，也通常无人查看。开启「闲时启用」后：

- 空闲时段：机器人照常响应，API 按半价计费；
- 高峰时段：入站消息不进入 Harness、不建会话、不调用模型，只回一条固定提示，**不消耗 token**；
- 平台连接与消息轮询保持正常，进入空闲时段的边界后立即恢复响应；
- 不会积压消息：高峰期消息不会在空闲时段补发（已随更新游标消费）。

## 2. 时段定义（DeepSeek 官方规则）

DeepSeek 官方定义：**北京时间周一至周五（不含中国法定节假日）09:00–12:00、14:00–18:00 为高峰时段**；其余时段均为空闲时段，价格为高峰时段的一半。

| 名称 | 北京时间（UTC+8） |
| --- | --- |
| 高峰（不调用模型） | 周一至周五 09:00–12:00、14:00–18:00，法定节假日除外 |
| 空闲（响应） | 工作日其余时间（00:00–09:00、12:00–14:00、18:00–24:00） |
| 空闲（响应） | 周六、周日全天 |
| 空闲（响应） | 中国法定节假日全天（含调休放假日期） |

补充规则（DeepSeek 官方 2026-09-19 说明）：**调休上班的周末也按周末计费**，即全天按空闲时段；因此周六、周日无论是否调休上班都全天空闲。

判断统一换算为北京时间（UTC+8）后计算，不受宿主时区或夏令时影响。实现见 `src/channels/shared/off-peak.mjs` 的 `DEEPSEEK_PEAK_WINDOWS`、`isPeakAt()`、`isOffPeakAt()`。

### 法定节假日表

内置 **2026 年**（国办发明电〔2025〕7号）与 **2027 年**（国办发明电〔2026〕10号）的国务院节假日安排：

- **2026 年**：元旦 1/1–1/3；春节 2/15–2/23；清明 4/4–4/6；劳动节 5/1–5/5；端午 6/19–6/21；中秋 9/25–9/27；国庆 10/1–10/7。
- **2027 年**：元旦 1/1–1/3；春节 2/5–2/13；清明 4/3–4/5；劳动节 5/1–5/5；端午 6/9；中秋 9/15；国庆 10/1–10/7。

### 同步节假日

设置页「法定节假日表」右侧有 **「同步节假日」按钮**：点击后 Host 从 [holiday-cn](https://github.com/NateScarlet/holiday-cn)（按国务院通知生成的年度 JSON）拉取**当前年份及未来两年**的放假日期，保存为 `syncedHolidays` 与 `syncedAt`（设置文档升级为 `version: 2`）。

- 内置 2026/2027 表与同步结果**合并生效**（取并集）；
- 同步失败时保留原有数据并提示「节假日同步失败，请检查网络后重试。」；
- 需要联网；未来年份尚未发布时会被忽略；
- 设置页显示「已同步 N 个节假日（最近同步：…）」或「尚未同步节假日；当前使用内置 2026、2027 年节假日表。」

## 3. 使用方法

1. 打开「设置 → IM机器人（个人版）→ 通用」；
2. 在「闲时启用」一行打开开关；
3. 开关下方会显示当前状态与时段说明：
   - **已开启，当前为空闲时段（半价），机器人正常响应。**
   - **已开启，当前为高峰时段，不调用模型，仅自动回复固定提示以节省 API 费用。**
   - **已关闭，机器人始终响应消息。**
4. 需要更新节假日时，点击「法定节假日表」右侧的「同步节假日」。

开关保存后**立即生效**，无需重启 DSH。微信与 QQ 共用同一个开关。

也可以直接调用管理 RPC（与设置页等价）：

```json
// settings.off-peak.get  → 读取
{ "ok": true, "value": { "enabled": true, "offPeakNow": false, "activeNow": false,
  "schedule": {
    "timezone": "Asia/Shanghai (UTC+8)",
    "peakWindows": [ { "start": "09:00", "end": "12:00" },
                     { "start": "14:00", "end": "18:00" } ],
    "weekdays": "周一至周五",
    "weekendOffPeak": true,
    "holidaysOffPeak": true,
    "builtinHolidayYears": [2026, 2027],
    "holidayDates": ["2026-10-01", "..."],
    "syncedHolidays": ["2028-01-01"],
    "syncedAt": "2026-11-10T07:00:00.000Z"
  } } }

// settings.off-peak.set  → 保存开关（同步的节假日不受影响）
{ "enabled": true }

// settings.off-peak.sync-holidays  → 拉取并保存未来年份的节假日
{ "ok": true, "value": { ...status... },
  "synced": { "years": [2026, 2027], "failedYears": [2028],
              "fetchedAt": "2026-11-10T07:00:00.000Z",
              "source": "https://raw.githubusercontent.com/NateScarlet/holiday-cn/master" } }
```

三个端点挂在现有 `/dsh-im-settings` 复合管理通道上（`plugin-src/host/off-peak-rpc.mjs`），鉴权沿用该通道的 `rpcAuthority`。

## 4. 行为细节

- **入站门控**：微信在 `WeixinRuntime.#runMonitor` 调用 `bridge.accept()` 之前判断；QQ 在 `QqRuntime` 的 `message` 事件处理器与 typing predicate 中判断；微信个人号桥接在生成回复前判断。
- **固定提示**：命中高峰且开关开启时，微信私聊会直接回复一条「呼…大肥鱼正在睡觉中，暂时没法回复消息，等空闲时段再来找我吧～」；QQ 仅对被 @/私聊的消息回复；微信个人号群聊仅对被 @ 的消息回复。提示由渠道桥直接发送，**不调用模型**；同一聊天 5 分钟内最多一条，避免刷屏。
- **不建会话**：消息不会到达 Harness，不会出现「正在输入」，不触发访问策略/命令处理。
- **轮询继续**：微信继续 `getUpdates` 并推进 `get_updates_buf`；QQ 保持 WebSocket 连接；个人号桥接继续消费 SSE 游标。进入空闲时段后无需重连。
- **只影响新的入站消息**：已经在执行中的任务、由主动投递或延迟交付触发的请求不受影响；计划任务在高峰期运行仍会调用 API。
- **故障放行（fail-open）**：设置文件缺失或损坏时按「关闭」处理；运行时判断失败也按「不拦截」处理。
- **状态持久化**：`$DSH_HOME/integrations/dsh-im/off-peak-settings.json`，当前格式 `{ "version": 2, "offPeak": { "enabled": true, "syncedHolidays": [], "syncedAt": null } }`，原子写入。v1 旧文件的 `extraHolidays` 会自动迁移为 `syncedHolidays`。删除该文件等价于关闭。

## 7. 已知限制

- 高峰窗口固定为 DeepSeek 官方定义，不提供自定义窗口；如官方调整计费规则，需要修改 `DEEPSEEK_PEAK_WINDOWS`。
- 内置节假日表覆盖 2026、2027 年；之后年份请点击「同步节假日」更新（或更新内置表后重新构建），否则只按周末规则判断。
- 固定提示有 5 分钟节流；高峰期多条消息可能只收到一条提示，且不补发。
- 该开关只拦截入站消息，不暂停计划任务、进行中的任务或主动投递。
