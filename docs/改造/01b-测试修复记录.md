## 5. 仍失败 / 跳过 / 已知遗留

### 5.1 最终全量中剩余 4 个失败（均非渠道裁剪测试）

1. `test/persona-ui.test.mjs` ×3：人设库 v2 正在并发实现，`test/persona*.test.mjs` 按任务约定不由本任务修改；本次运行中它们先通过后失败，取决于人设任务当时的源码状态。以人设任务最终结果为准。
2. `test/client-i18n-bundle.test.mjs` ×1：该测试直接加载发布产物 `lib/client.js` 并与当前源码词典比对，用于发现过期 bundle。persona 任务在 `plugin-src/client/i18n.js` 新增了 `config 人设` 等词条后，`lib/client.js` 尚未重新构建（本任务按约束不运行 `npm run build`）。**Lead 最终执行 `npm run build` 后该测试即恢复通过**。

### 5.2 唯一 skipped 用例（源码契约问题，Lead 决定不改源码）

`plugin-src/host/delivery-service.mjs` 的 `sendChecked` 回执分支仍比较 `result.receipt.conversationId !== target.route.chatId`。`chatId` 是随飞书（Lark 卡片 / AI Card）契约一起存在的字段，微信/QQ 路由只有 `toUserId` / `userOpenId` / `groupOpenId`，因此该分支在个人版是**飞书移除后的死路径**。Lead 决定：不改源码，保留 `test.skip` 并在报告注明“飞书专属契约，个人版渠道不支持”；后续可整体移除 checked-delivery 契约（已记入 `docs/改造方案.md` 的已知遗留）。
