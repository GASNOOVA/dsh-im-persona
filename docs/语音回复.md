# 语音回复与 B 站翻唱（voice-hub）

> 部署与迁移的完整环境说明（GPU 驱动、torch 版本、Pascal 限制、GPT-SoVITS 与
> song2cute）见 [GPU 声音服务部署](GPU声音服务部署.md)。

> 状态：插件侧已实现并验证语音条发送与 B 站翻唱指令解析
> （v5.10.0-personal.17）。实际出声需要另外部署 `voice-hub`
> （`tools/song2cute/voice_hub.py`，需要 GPU）。默认关闭。

## 为什么需要单独的声音服务

大肥鱼声线（cute / gentle）来自 `astrobot_plugin_feiyu_voice` 仓库的 CosyVoice3
模型与参考音频，模型权重约数 GB，且推理必须在 CUDA / ROCm / Intel XPU 上运行。
本仓库不携带模型，也不在插件进程里跑推理，因此采用「HTTP 声音服务 + 插件客户端」
的方式：

```
微信个人号桥接                        本机 / GPU 机器
┌──────────────────┐  HTTP 9860  ┌───────────────────────────────┐
│ 群消息 → 模型生成 │ ──────────► │ voice-hub                     │
│ 语音/翻唱指令解析 │  提交+轮询  │  ├─ TTS：GPT-SoVITS :9850    │
│ <dsh_im_voice>   │ ◄────────── │  └─ 翻唱：song2cute (Demucs+RVC)│
└──────────────────┘  下载音频    └───────────────────────────────┘
        │
        │ 语音：上传 WAV → sends(kind=voice)
        │ 翻唱：上传 MP3 → sends(kind=file)
        ▼
  agent-wechat daemon → 微信语音条 / 文件
```

## 部署声音服务

### 从 DSH 主机访问 server 上的 voice-hub

server 的防火墙默认只允许本机访问 9860、9850。若 DSH 与 GPU server 不在同一台机器
（例如本项目的 DSH 主机 192.168.2.112、server 192.168.2.106），请在 DSH 主机上建立
SSH 隧道，再把插件里的服务地址填成 `http://127.0.0.1:9860`：

```bash
ssh -F /dev/null -o IdentitiesOnly=yes -i ~/.ssh/id_ed25519 \
  -N -L 127.0.0.1:9860:127.0.0.1:9860 cc@192.168.2.106
```

本仓库提供脚本 `/mnt/volume/dsh/voice-hub-tunnel.sh`（实际路径以部署机为准）：
`nohup /mnt/volume/dsh/voice-hub-tunnel.sh >> /mnt/volume/dsh/voice-hub-tunnel.log 2>&1 &`。
隧道断开时语音/翻唱会自动回退为文字，重新建立隧道后无需改插件配置。

推荐部署本仓库自带的 **voice-hub**（`tools/song2cute/voice_hub.py`）：一个 FastAPI
网关，同时提供 feiyu 兼容的 TTS 接口和 B 站翻唱接口，串行使用同一块 GPU。部署步骤与
依赖见 [GPU 声音服务部署](GPU声音服务部署.md) 的「服务 D：voice-hub」。

如果只想用原版 feiyu 声音服务，也可以继续在带 GPU 的机器上按
`astrobot_plugin_feiyu_voice/server/` 的 `INSTALL_AGENT.md` / `RUNTIME.md` 部署：

1. 安装 Python 3.11 与对应 GPU 的运行时（CUDA / ROCm / XPU），运行
   `python scripts/setup_runtime.py --backend cuda` 等脚本；
2. 从 HuggingFace/ModelScope 下载 `FeiyuVoice-CosyVoice3`（含 cute、gentle 两条声线）
   与 `FeiyuVoice-RVC`；
3. 启动服务：`python -m feiyu_voice_service`（默认 `http://127.0.0.1:9880`，可加
   `--host 0.0.0.0` 供其他机器访问）；
4. 服务会生成 `.runtime/voice-service/api_key.txt`，把该文件路径填到插件里。

## 插件内配置

设置 → **IM机器人** → **通用** → **群聊大脑** → **微信个人号（agent-wechat）**
→ **语音回复**：

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 启用语音回复 | 总开关；关闭时模型输出里的语音标签会被忽略 | 关 |
| 语音模式 | `标签触发`：只有模型主动使用语音标签才发语音；`始终语音`：每条普通回复都先发语音条，失败自动回退文字 | `标签触发` |
| 声音服务地址 | voice-hub（或 feiyu）的 HTTP 地址 | `http://127.0.0.1:9880` |
| API Key 文件路径 | 服务的 api_key 文件；插件只读、不显示内容；留空表示无鉴权 | 空 |
| 声线 | `cute`（默认）或 `gentle`（voice-hub 目前固定 cute） | `cute` |
| 单条语音最多字数 | 超过会截断，避免生成过慢/过长 | 300（20–600） |

「测试声音服务」按钮会调用 `POST /v1/speech` 合成一句测试语音并返回字节数，用来
确认地址、Key 与模型都可用。

### B 站翻唱（voice-hub）

在同一个「微信个人号」区块还有 **B 站翻唱（voice-hub）** 子区块：

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 启用 B 站翻唱 | 允许群成员用「引用 + B 站链接 + 翻唱」触发翻唱 | 关 |
| 翻唱服务地址 | voice-hub 地址，通常与语音服务相同 | 空 |
| API Key 文件路径 | 同上，插件只读 | 空 |
| 翻唱提示词最多字数 | 从引用消息里提取的要求上限 | 300（20–600） |

翻唱指令格式：发送包含「翻唱」两个字的文本，并让 B 站视频链接可被解析到。链接可以：

1. 直接写在同一条命令里（推荐）；
2. 在**被引用的那条消息**里（引用一条链接卡片/含链接的消息，再发「翻唱 + 要求」）；
3. 是**本群最近 10 分钟内**出现过的 B 站链接（先发链接、再单独说「翻唱」）。

例如以下三种都能触发：

```
翻唱 https://www.bilibili.com/video/BV1xx411c7mD 温柔一点

（引用一条含链接的消息后发送）
来翻唱一下这首歌，温柔一点

（先发一条链接，再发送）
给我翻唱一下 温柔一点
```

链接同时支持 `bilibili.com/video/BV…`、`av…` 与 `b23.tv` 短链。

- 默认输出**纯人声版**；只有提示词里出现「混音 / 带伴奏 / 伴奏版」才生成混音版；
- 接受任务时先回一条简短确认（大肥鱼语气）；后台从 B 站提取音频、跑 Demucs + RVC，完成后只把 MP3
  以文件形式发回群里（超过 60 秒的翻唱无法作为语音条）；
- 提示词里的「升调 / 降调 / 温柔 / 清晰」会被保守映射为 RVC 参数，其余文字仅作说明；
- 服务端有单曲时长上限（默认 8 分钟）与临时文件 TTL（默认 2 小时 / 20 GiB）；
- 失败时机器人会回一条错误摘要（B 站风控常见 HTTP 567，插件会自动重试整轮下载以换 CDN；仍失败可稍后再试）。

## 语音标签与语音模式

桥接层在模型回复中识别：

```
<dsh_im_voice>要朗读的文字</dsh_im_voice>
```

- 标签前/后的普通文字照常以文字发送；标签内的文字单独合成为**一条微信语音条**；
- 一条回复只支持一个标签；标签文字超过「单条最多字数」会截断；
- 语音发送后，群里会显示微信语音条（type 34），并额外记一条 `[语音] …` 到群记忆；
- 合成/上传/发送任一环节失败，朗读文字会并回普通文字消息，不会丢内容；
- 群聊 @ 直通回复会带 @ 提及；自动接话/连续对话的语音条不带 @。

「标签触发」模式下，只有模型主动要求（例如「用语音说一句」「发条语音」）时才会输出
标签；「始终语音」模式下，桥接层会把普通回复按标点拆成最多 4 段（每段 ≤180 字），
逐段合成为语音条，全部失败时回退普通文字。相关指令会随 prompt 注入，模型也可以拒绝。

## 群内注入式指令

群消息里可以直接发送下面两条指令（不会进入模型，指令本身也会记入群聊记录）：

| 指令 | 作用 | 示例 |
| --- | --- | --- |
| `#语音模式` | 切换当前群的语音回复开关；也可以显式指定开/关 | `#语音模式`、`#语音模式 关`、`#语音模式 开` |
| `#闭嘴` | 停止当前连续对话窗口内的自动接话，直到下一次被 @ 唤醒；自动搭话/主动发言不受影响 | `#闭嘴` |

说明：

- `#语音模式` 关闭后，本群所有语音路径（始终语音与标签触发）都会改用文字；再次发送或
  `#语音模式 开` 恢复。该开关保存在插件进程内存里，插件重启/HMR 后回到配置默认值。
- 发送 `#语音模式` 会先被当作注入式指令处理，不会交给模型；插件会回一条很短的文字确认。
- 翻唱任务进行中、或远端 voice-hub/声音服务不可达时，插件会自动改用文字回复；连接恢复后
  下一次回复会重新尝试语音（健康检查 60 秒缓存）。
- 接受翻唱指令时只回一条简短确认；完成后**不再发「翻唱完成」文字**，直接发文件；失败时才回错误摘要。
- 闲时固定提示、语音模式确认、`#闭嘴` 确认、翻唱确认等预设自动回复已统一为大肥鱼人格语气。

## 发送链路

1. `FeiyuVoiceClient.speak({ text, style })`：`POST /v1/speech` → 轮询
   `GET /v1/jobs/{id}` → `GET /v1/jobs/{id}/audio`，返回 WAV 字节；
2. `AgentWechatClient.uploadMedia({ name, bytes, mediaType: 'audio/wav' })`：
   `POST /v1/accounts/{account}/uploads` 得到 `sourceId`；
3. `AgentWechatClient.sendVoice({ threadId, sourceId })`：
   `POST /v1/accounts/{account}/sends`，body `{ kind: 'voice', threadId, sourceId }`；
4. daemon 用内置 FFmpeg 转码，按微信 60 秒/条上限切分后发送。

> agent-wechat 发送语音需要 FFmpeg/FFprobe。本仓库的部署已把静态 ffmpeg/ffprobe
> 放在 daemon 目录的 `bin/` 下，插件启动 daemon 时会把该目录前置到 `PATH`。

## 已知限制

- 需要另一台带 GPU 的机器（或 WSL/Colab）跑声音服务；插件本机不跑模型；
- 插件侧不校验声线是否存在，只透传 `cute` / `gentle`；
- 单条微信语音受协议 60 秒限制，长文本会被 daemon 拆分为多条；
- 语音服务鉴权为 Bearer API Key，Key 仅从文件读取，不进入日志/设置响应；
- 语音回复会增加一次模型生成之外的 TTS 延迟（取决于 GPU 与服务队列）。
