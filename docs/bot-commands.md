# Command details

**Permission presets (Weixin and QQ)**: `/permission` reads the current bound session. `/permissionlist` lists the Host's available presets in numbered order and marks the current value. `/permission 2` uses the latest list in this bot and chat; `/permission workspace-write` accepts an ID without listing first, and `/permission id:123` addresses a numeric ID. Numbered lists expire after 15 minutes or a bot restart; switching the bound session requires a new list. Reordering the Host catalog never changes the ID behind a previously displayed number. Commands require an existing session and plain text, follow existing command permissions, and remain responsive during a running turn. A switch takes effect on the current session and updates sandbox and approval policies together; it does not change defaults for new sessions. Full access switches in one command without a second confirmation. Existing tool executions and pending approval requests are not replayed or automatically approved. The Host owns available presets and their meaning; `custom` is display-only.


**QQ menu**: Send `/m` or `/menu` to open the assistant menu. Its twelve entries are session selection, workspace, mode/preset, model, new session, session list, stop, compact, steering, archived-session visibility, status and help. Selectors open paginated button lists instead of dropdowns. Buttons send an opaque menu selection through the existing command path. If QQ rejects buttons, the same menu is sent as numbered text. Reply with the number from the latest menu; numbers are scoped to the chat and the person who opened it. Menus expire after 15 minutes, restart, ordinary input or another command. Old buttons are rejected when the session or workspace changes. Questions, approvals and batch input keep priority over numeric selection. Stop and steering remain usable during a task; switching sessions/workspaces, starting a new session and compacting require the current task to finish. Custom steering uses `/steer <instruction>`. Archived-session visibility only filters the menu and survives restarts; it does not archive or delete sessions. Session watches and a reasoning-level selector are not part of this menu.


Example: send `/models`, then `/model 2` to switch to the second model in the list; send `/reasoninglist`, then `/reasoning 2` to switch to the current model's second reasoning effort; send `/presetlist`, then `/preset 2` to select the second Agent Preset for this bot. Other examples: `/help`, `/new`, `/status`, `/version`, `/model deepseek-official/deepseek-v4-pro max`, `/reasoning --default`, `/preset marketing-jeep`, `/preset --default`, `/steer inspect only the configuration file`, `/stop`, `/compact`, `/clear`, `/workspace /Users/alice/projects/my-app`, `/ws 2`, `/wsl`, `/sessionlist 2`, `/sessionlist /Users/alice/projects/my-app`, `/session session-id`, `/history`, or `/history 5`




- `/help` takes no arguments and never creates a Session. It returns the complete command list supported by the current bot.
- `/status` takes no arguments, never prompts the model, and does not change the Session binding. It confirms that the current bot can reach DeepSeek Harness, then reports the effective workspace, the bound Session (or that none is bound yet), the current model and this bot's Agent Preset; when this chat's Session is running, one more line says so. The reply is always one message, and a field that cannot be read right now is omitted instead of failing the command. These details are shared by the Weixin and QQ bridges.
- `/version` takes no arguments and never contacts Harness, creates a Session, or prompts the model. It returns the version of the running dsh-im plugin.
- `/new` only removes the current chat's saved dsh-im Session binding; it never deletes, empties, or archives the old Session. The next ordinary message creates and binds a new Session in the current workspace. If a task is running or waiting for a question or approval, finish the interaction or use `/stop` before `/new`.
- `/models` takes no arguments and never creates a Session. It assigns a number to every currently configured Harness model and also shows its stable, copyable `provider/model-id`. If one provider fails, models from the remaining providers are still shown.
- Bare `/model` shows the current Session model and reasoning effort. With arguments, it accepts a number from `/models` or an exact full model ID, followed optionally by an exact reasoning effort ID published in that target model's metadata, for example `/model 2 max`. When the effort is omitted, Harness resolves the target model's current default. If the chat has no Session yet, a valid switch creates and binds a blank Session without prompting the model.
- `/reasoninglist` and `/reasonings` are equivalent. They list the efforts from the current model's metadata and mark the current and default values. `/reasoning` shows the current value; `/reasoning <number or effort ID>` accepts a listed number or an exact metadata ID; `/reasoning --default` lets Harness resolve the current model's default again. Every `/reasoning...` command requires an existing Session and never creates one or prompts the model.
- The model or reasoning effort cannot be changed while a task is running or waiting for an approval or question answer. Wait for it to finish or use `/stop` first. A change takes effect on the next model request and keeps Harness's default-saving semantics: Harness attempts to save the accepted model and effort as the default selection for future Sessions, while other existing Sessions remain unchanged. A Session containing images cannot switch to a model that does not accept image input.
- `/presetlist` and `/presets` are equivalent. They take no arguments and never create a Session. Each reads the Host's currently available Agent Presets, showing their names, stable IDs, the Host default, and this bot's selection. A selected Preset that has been deleted or become broken is retained and marked unavailable instead of being cleared automatically. Only safe names and IDs are shown; paths, errors, and other Host internals are never exposed.
- Bare `/preset` shows this bot's setting for future new Sessions; it does not inspect or change the current Session. With an argument, it accepts a number from the most recent `/presetlist` in this chat or an exact ID; use `/preset id:<ID>` for a numeric ID. A numbered selection resolves the ID from that displayed list and then validates it against the latest Host catalog, asking for a fresh list if it has changed.
- `/preset --default` clears this bot's explicit override so future Sessions resolve the Host default when they are created. Explicitly selecting an ID that currently matches the Host default pins that ID instead. Following the Host default remains available even while the catalog cannot be read.
- An Agent Preset change is bot-wide: it affects future new Sessions in every chat for this bot, but never modifies, stops, unbinds, or rebuilds an existing Session and never runs `/new` automatically. If this chat already has a Session, ordinary messages keep using it; the first ordinary message after `/new` creates a Session with the new setting. Presets can still be queried or changed while a task is running or awaiting interaction because the command does not touch that Session.
- `/stop` and `/steer` control only a running task started by this chat. Even when multiple chats bind the same Session, they do not intentionally control another chat's task. `/stop` does not delete the Session or its history, preserves queued work that has not started, and is safe to repeat.
- `/steer` accepts text only, including multiple lines. It neither creates another Session nor starts a second task. Send an ordinary message when no task is running; while an approval or question is pending, answer it first or use `/stop`.
- `/batch`, `/send`, and `/cancel` are available only in a direct chat with the bot. After `/batch`, subsequent text-only messages are held temporarily, up to 10 messages. The tenth is collected and prompts you to submit; later messages are rejected and the batch is never submitted automatically. `/send` processes the collected messages in their original order as one input, while `/cancel` discards them. Images, files, quoted messages, and other commands are not collected. Starting a batch requires a plain-text `/batch` without a quote, image, or file. While collecting, a quoted `/send`, `/cancel`, or repeated `/batch` still submits, cancels, or reports progress. A submission contains only the collected text; any quote or attachment on the command message is excluded. An unsubmitted batch is lost if the bot restarts. Ordinary chat behavior is unchanged when batch input is not active.
- `/compact` acts only on the Harness Session already bound to the current chat and is never sent to the model. The bot reports the applicable status when the chat has no Session yet, the Session is generating a reply, or there is no compactable history.
- `/clear` acts only on the Harness Session already bound to the current chat: it clears model context while retaining the Session binding and history. It never unbinds, deletes history, or silently runs `/new`. If the current Host has not registered `/clear`, the bot reports that explicitly and leaves the Session unchanged. While a task or interaction is active, finish it or send `/stop`; arguments, images, and files return usage.
- The path must be an existing absolute directory. The bot returns an actionable error and the correct usage when validation fails.
- `/conv` (aliases `/conversation` and `/thread`) shows the current conversation's workspace and lists available workspaces with their indexes. Each group topic or direct chat can use its own workspace; without an explicit binding it follows the bot default.
- `/conv N` or `/conv /absolute/path` pins a workspace for only the current conversation. Pinning the current bot default is also explicit: later changes to the default do not move that pin. A changed binding clears this conversation's old Session mapping, so subsequent messages use its selected workspace.
- `/conv clear` or `/conv --default` removes the conversation's explicit binding and follows the bot default again. `/workspace` and `/ws` continue to change the bot-wide default; use `/conv` when a change should apply only to this conversation.
- `/workspace` and `/ws` are the same command: without an argument they list the switchable workspaces. Channels without card support keep receiving the original text list. `/workspace N` and `/ws N` switch using the freshly resolved list order at execution time; absolute paths remain supported.
- `/workspacelist`, `/workspaces`, and `/wsl` still work when typed and are equivalent to the no-argument form of `/ws`; they no longer appear in native command menus, which keep a single workspace entry. They combine the Harness global registry with the current bot's path, putting the current path first and marking it as current when it still exists.
- Without a workspace argument, `/sessionlist` and `/sessions` list the current conversation's effective workspace. `/session N` selects from that same workspace's current session list; an explicit workspace argument to `/sessionlist` still selects that workspace.
- `/sessionlist` and `/sessions` are equivalent. A numeric argument uses the same freshly resolved order as `/workspacelist` at command execution time. An absolute path can also select a workspace directly, and the result echoes the resolved path.
- `/sessionlist --limit N` and `/sessions --limit N` limit only that command's response. They do not change any global or bot setting, and omitting `--limit` still lists every session.
- `/sessionlist --all` (and `/sessions --all`) summarizes sessions across every registered workspace in one answer, keeping the current workspace first and marking it; `--all --limit N` sets the per-workspace cap, which defaults to 10. A workspace whose list cannot be read is left out instead of failing the whole summary, the summary says how many workspaces were skipped, and a truncated group says how many sessions it holds.
- The session this chat is already bound to is marked `(currently bound)` in the list, so the list answers "where am I" without a separate lookup.
- `/sessionarchive <Session ID>` (alias `/sessarchive`) archives one Session through the Harness (`workspace.archiveSession`). A numerical argument only previews the Session behind that index (title, workspace, ID) and never archives: the list shifts as Sessions are created, so a destructive action must name the Session explicitly. The bot resolves the target, refuses the Session this chat is bound to and one that is already archived, and reports what the Host said; `--stop` asks the Host to stop that Session's running work instead of refusing. Archived Sessions disappear from the default `/sessionlist` (see `--archived`).
- Both session-list aliases list every live session registered to the selected workspace. Archived sessions are hidden by default: the answer says how many were hidden and `--archived` lists them afterwards, unnumbered, because an index is only meaningful for the sessions `/session N` can bind. Blank and subagent sessions are included when they belong to that workspace; sessions without a title are shown as `No title yet`. Any listed ID — archived ones included — can be passed directly to `/session Session ID`.
- New bots default to `$DSH_HOME/im` (`~/.dsh/im` when unset); an explicit channel `workspace` takes precedence and `dshHome` overrides the environment variable. The directory is created automatically and sessions created there remain ungrouped. For this directory, session lists also include ungrouped sessions with a matching working directory, while excluding sessions assigned to other workspace groups. Ordinary ungrouped sessions there can be bound by ID or current-list index. Other directories retain registry-based listing and binding.
- `/session` accepts exactly one argument: a full Session ID from `/sessionlist`, a positive index in the current conversation workspace's session list, or a single title keyword. `/sess` is a short alias for the same command, for clients that claim `/session` for a native slash command; it takes identical arguments and is listed in `/help` (the native menu registers the primary name only). It neither creates a session nor immediately prompts the model; later messages in the current chat continue the bound session. Regular archived sessions can be bound without being unarchived, while subagent sessions cannot be bound.
- A title keyword is matched case-insensitively, searching the current conversation workspace first and then the other workspaces. The keyword must be a single token (no spaces); a purely numeric argument is still treated as an index. A single match in the current conversation workspace binds directly. A single match in another workspace, several matches, or an incomplete search (when some workspaces cannot be read) list the candidates with their workspace and ID and bind nothing until the full Session ID is given; this avoids moving the bot workspace and clearing other chats' bindings from an accidental keyword. Archived Sessions are never taken over by a keyword: when only archived titles match, the answer names them and asks for the full Session ID instead. No match keeps the previous behaviour, so the argument is still tried as a Session ID. A token starting with `session-` is always treated as an ID and never as a keyword.
- An exact non-prefixed ID takes priority over title matches even when its title is empty or the title candidate list is truncated. Binding by title preserves the bot default and other chats' bindings, including when this conversation pins a different workspace with `/conv`. If that workspace changes during the search, the stale selection is rejected.
- `/history` works identically in direct chats on Weixin and QQ. It only reads the Session already bound to this chat: it never creates a Session, prompts the model, or interrupts running tasks or pending interactions. It returns the latest 3 messages by default. `/history N` accepts a positive integer, caps values above 5 at 5, and returns fewer when fewer are available. Zero, negative, fractional, nonnumeric, and multiple arguments show usage; commands with images or files are rejected. While collecting batch input, use `/send` or `/cancel` first.
- A user message or a final assistant reply counts as one history item, not one turn or day. The latest N items are displayed oldest first. Tool events, reasoning, injected content, and unfinished assistant output are omitted; old attachments are not downloaded or resent. Long text is marked as truncated, with at most 3 text segments per reply and no automatic pagination. After binding a Session, send `/history` manually; binding never replays history automatically. Message text may still contain sensitive information from the original conversation, so expose the bot only to trusted users.
- `/session` locates the session's unique workspace automatically. Binding inside the current workspace replaces only this chat's mapping. A cross-workspace binding switches the bot workspace, clears the old session mappings for all of that bot's chats, and then binds this chat, so it affects the bot's other chats. A reply already being generated may still finish.
- When `/session` adopts a Session from a different workspace than this conversation's pin, it removes the conflicting pin so the reported workspace agrees with the bound Session. A pin to the same workspace is preserved. Running `/conv` afterwards can establish a new pin for this conversation.
- Workspace switches and session bindings only clear or replace dsh-im chat mappings. They never delete, empty, or archive old Session contents; an old Session can still be listed and bound again.
- Any user admitted by the current channel access policy can run these commands; there is no separate administrator role. Weixin admits the owner and allowlisted direct-chat users only; QQ admits the owner and, in groups, the members allowed to mention the bot.
- Agent Preset names and IDs come from the same Harness Host, and any command-authorized user can change the Preset used by all future new Sessions across this bot's chats. Expose `/presetlist` and `/preset` only to trusted users.
- The list comes from the Harness Host's global registry and can include local absolute paths for other bots, other channels, or non-IM projects. Restrict the bot's visibility to trusted users.
- Session results also come from the global Harness Host. Session IDs and titles can belong to other bots, other channels, or non-IM projects, and may contain sensitive metadata. Enable these commands only when every user in the bot's visibility scope is trusted.
- Any user who can run `/session` can continue the selected session and use later messages to write to it or invoke its available tools. Expose the bot and session list only to trusted users.
- A successful switch clears only the current bot's old Harness session mappings and does not affect other bots.
- The new workspace applies to subsequent messages; a reply that has already started generating is allowed to finish.
