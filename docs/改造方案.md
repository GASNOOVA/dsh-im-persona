# dsh-im 个人定制版改造方案

> 仓库：`dsh-im-persona` · 基线：`@xmanrui/dsh-im` v5.10.0（commit `fc2ceab2`）· 定位：**独立个人版，不再追上游**
>
> 本文档是本次改造的总纲：说明改了什么、为什么这么改、剩下的活怎么干、怎么验收。渠道裁剪细节见 [01-渠道裁剪](改造/01-渠道裁剪.md)，人设能力设计与接入见 [02-人设能力](改造/02-人设能力.md) 与 [02b-人设接入记录](改造/02b-人设接入记录.md)，来源与基线见 [00-来源与基线](改造/00-来源与基线.md)。

## 1. 目标与范围

用户最终确认的四项目标：

| # | 目标 | 本次落地 |
| --- | --- | --- |
| 1 | **品牌独立**：包名 / 插件标识 / 仓库 / 作者改为个人版 | `@xmanrui/dsh-im` → `dsh-im-persona`；面板、样式、GitHub 链接、README、安装器全部个人化 |
| 2 | **新增人设能力**：每个机器人可配置角色、语气、自定义提示词 | 新增 Persona 模块（存储 / RPC / 设置页 / 入站注入），详见 02 文档 |
| 3 | **精简渠道**：只保留实际使用的 IM 渠道 | 只保留 **微信（weixin）** 与 **QQ（qq）**，移除其余 12 个渠道 |
| 4 | **深度个人化**：UI / 交互 / 默认配置 | 移除「从 npm 检查上游更新」；渠道顺序固定微信→QQ；默认值与设置项按个人使用收敛 |

明确不做的：

- **不追上游**：不保留 `upstream` remote，不承诺 `git merge` 上游；上游修复按需人工移植。
- **不做多用户 / 多租户**：本插件只服务本机个人使用，"访问模式"仅保留必要的安全边界。
- **本次不要求完整构建与测试通过**：交付物是「可继续开发的仓库骨架 + 改造方案」，构建与验收命令见第 7 节，作为下一步执行清单。

关键机制（沿用上游，个人版不重写）：

1. **设置页**：`plugin-src/client/index.js` 在 `settings.section` 注册一个 `dsh-im-persona` 页签（order 21），内部渲染微信/QQ 渠道卡片。
2. **渠道 Host**：`plugin-src/host/channels/<channel>/index.mjs` 的 `apply(ctx, config)` 装配「连接监督 + RPC + 运行时」。
3. **会话**：每个 (`botId`, 会话路由) 绑定一个 Harness Session；工作区、模型、Agent Preset 按机器人独立保存。
4. **入站消息**：渠道桥 → 共享语义层（引用/上下文增强/人设注入）→ Harness Session。
5. **数据目录**：`$DSH_HOME/im`（默认工作区）、`$DSH_HOME/integrations/dsh-*`（各渠道状态/凭据）；**个人版不改数据目录名**，已装过上游插件的旧数据可继续读取。

## 4. 渠道裁剪（微信 + QQ）

原则：**保留微信/QQ 的完整用户价值，删除其余渠道及其共享依赖**。删除范围覆盖 5 层：协议层（`src/channels/*`）、Host 外壳（`plugin-src/host/channels/*`）、Web 客户端（`plugin-src/client/channels/*`）、测试（`test/`）、脚本/文档/资源。

结果预期：

- `src/channels/` 只剩 `weixin/`、`qq/`、`shared/`；
- 设置页只剩「微信」「QQ」两张渠道卡片，顺序固定微信在前、QQ 在后；
- 依赖从 10 个运行时包收敛到微信/QQ 所需（QQ 官方 SDK、`qrcode`、`undici` 等）；
- `scripts/verify-channel-trim.mjs` 静态扫描通过：无悬空相对 import、无被移除渠道标识残留。

细节、完整清单与依赖建议见 **[01-渠道裁剪](改造/01-渠道裁剪.md)**。

## 5. 人设（Persona）能力

**一句话**：内置「大肥鱼」人设 + 可导入的人设库；每个机器人从中选择一份（或自定义），注入到该机器人的每条普通用户消息，让微信/QQ 里的助手拥有稳定、可切换的角色。

参考实现：用户的独立人设插件 [`dsh-persona-dafeiyu`](https://github.com/huaizhuanghub/dsh-persona-dafeiyu)（MIT）。本版整合其内置 **大肥鱼** 角色正文，并保留同类的**外接自定义人设**能力（导入/管理/查看全文）。

```text
HTTP/RPC:  bot.persona.get/set(botId)            ← 每机器人选择（不使用 / 人设库 / 自定义）
           persona.library.list/get/import/rename/remove   ← 人设库管理
存储:      $DSH_HOME/integrations/dsh-im/personas.json         （每机器人选择，v2）
           $DSH_HOME/integrations/dsh-im/persona-library.json  （导入的自定义人设）
           内置大肥鱼：源码常量 src/channels/shared/persona-presets.mjs（不可删改）
注入:      用户消息 → 上下文增强来源块 → <dsh_im_persona> 人设块 → Harness Session
```

人设库设计（对齐参考实现、按需裁剪）：

| 能力 | 说明 |
| --- | --- |
| 内置人设 | `dafeiyu`（大肥鱼）：name/description/text 来自 `dsh-persona-dafeiyu` 的 `BUNDLED_DAFEIYU`，不可删除、不可覆盖；正文随源码维护 |
| 导入 | 设置页粘贴正文或选择 `.md/.markdown/.txt` 本地文件；名字 ≤60 字符、正文 ≤64,000 字符 |
| 管理 | 重命名、删除（仅导入项）、查看全文（列表只返回元数据，正文按需单条拉取） |
| 外接文件 | 插件 config `personaFile`（绝对路径）作为只读 `config` 条目；文件缺失/不可读时 fail-soft |
| 每机器人选择 | `source: 'library'` 选库内人设；`source: 'inline'` 保留原「角色名/性格语气/补充要求」自定义；v1 数据自动迁移 |

设计约束（与上游语义一致）：

- 人设属于**用户消息内容**，不是系统提示词：不修改 Harness 系统提示词、工具和权限，因此不需要 Host 高权限接口，也不会影响其他插件的 Agent 组装；
- 命令（`/...`）、审批回答、问题回答不注入，避免人设污染控制链路；
- 与 Agent Preset、上下文增强、引用回复共存：人设块排在来源块之后、正文之前，长度受统一上限保护；
- 人设是机器人级配置，`/new` 后仍然生效；已有会话的后续消息同样注入，历史已写入内容不回溯；
- 人设库内置两条：**大肥鱼**（私聊版）与**大肥鱼（群聊版）**（独立 builtin，群聊准则 + 私聊版原文），原私聊版正文不改；群聊大脑回复时若机器人选中私聊版，会额外叠加同一套群聊准则；
- 人设库导入/管理只通过本机管理 RPC（沿用 `rpcAuthority` 鉴权），浏览器端读取文件内容、路径不出本机；
- 后续如需"真正的系统级人格"，可在 Host 侧用 `systemPrompt` 贡献实现（设计文档已给出升级路径，本次不实现）。

字段、RPC、UI、i18n、命令与测试的完整设计见 **[02-人设能力](改造/02-人设能力.md)**，用户指南见 [人设库](人设库.md)，实际接线记录见 [02b-人设接入记录](改造/02b-人设接入记录.md)。

## 6. 深度个人化

### 6.1 移除「检查并安装更新」

上游更新面板会访问 npm 上的 `@xmanrui/dsh-im`，在个人版中这是**危险的**：点"更新"会用上游包覆盖个人版。个人版整体移除该功能：

- Host：删除 `update-rpc.mjs`、`update-runtime.mjs`、`update-service.mjs` 及其安装调用；
- Client：删除 `update-panel.js`、主面板的更新入口与 `updateRpcCall`；
- 测试：删除 `test/update-*.test.mjs`，清理其他测试中的更新桩；
- 脚本/文档：`scripts/verify-package.mjs` 移除更新文件期望，删除 `docs/检查与安装更新.md` 等文档。

升级个人版的方式变为：`git pull` 后重新 `npm install && npm run build`，再重启 DSH（README 写明）。

### 6.2 默认配置与交互（个人习惯）

| 项 | 上游默认 | 个人版 |
| --- | --- | --- |

| 渠道数量 | 11 个 IM 渠道 + AI Office | **2 个** |
| 更新检查 | 自动查询 npm 并支持一键更新 | **无此功能** |

### 6.3 闲时启用（节省 API 成本）

需求：只在 DeepSeek API 非高峰时段响应消息，高峰期不调用 API，以节省费用。个人版实现为**全局开关**，微信与 QQ 共用：

- 时段（按 DeepSeek 官方定义）：北京时间周一至周五（不含中国法定节假日）09:00–12:00、14:00–18:00 为高峰；其余时间包括周末全天与法定节假日全天为空闲时段，价格为高峰的一半。调休上班的周末也按周末计（全天空闲）。判断按北京时间（UTC+8）计算，不随宿主时区/夏令时变化；内置 2026、2027 年国务院节假日表，设置页「同步节假日」按钮可从 holiday-cn 拉取未来年份（`src/channels/shared/holiday-sync.mjs`），设置文档 v2 保存 `syncedHolidays`/`syncedAt`（v1 的 `extraHolidays` 自动迁移）。
- 存储：`$DSH_HOME/integrations/dsh-im/off-peak-settings.json`，文档 `{version:1, offPeak:{enabled:boolean, extraHolidays:string[]}}`，默认关闭，原子写、懒加载、损坏 fail-open（`off-peak-settings-store.mjs`）。
- 门控：微信在 `WeixinRuntime.#runMonitor` 调 `bridge.accept()` 之前；QQ 在 `QqRuntime` 的 `message` 处理器与 typing predicate 中。命中时整条消息丢弃（不回复、不建会话、不调模型），但平台轮询/长连接继续、游标继续推进。
- 管理 RPC：`settings.off-peak.get/set`，并入现有 `/dsh-im-settings` 复合通道（`plugin-src/host/off-peak-rpc.mjs`、`inbound-ttl-rpc.mjs`）。
- 设置页：「通用」页签新增开关，显示当前时段状态与高峰窗口；支持编辑额外节假日（`YYYY-MM-DD` 每行一个）；保存失败回滚并允许重试。
- 测试：`test/off-peak.test.mjs`、`test/off-peak-settings-ui.test.mjs`，以及两个渠道运行时的丢弃/正常响应用例；`verify-package.mjs` 的可勾选控件计数同步更新（switch 1→2、checkbox 4→5）。

使用说明见 [闲时启用](闲时启用.md)。

### 6.4 群聊大脑（实验性，QQ + 微信个人号）

需求（用户 m01739 / m01919）：只做微信群聊，@ 时走明确提示词，为大肥鱼增加群聊 persona 并允许未 @ 自动接话，群聊记录永久保存且默认每 30 天压缩为长期记忆，一段讨论结束后按话题自由评论，小群（<5 人）成员分别建立画像并在回复时参考。

实现为**渠道无关核心** + QQ 接线：

- 核心 `src/channels/shared/group-brain/`：`group-brain-config.mjs`（配置/白名单/存储）、`group-store.mjs`（永久消息、记忆、状态）、`member-profiles.mjs`（成员画像）、`group-trigger.mjs`（静默触发与限流）、`group-context.mjs`（@ 指令块、记忆/画像块、接话与整理 prompt）、`group-brain.mjs`（编排：记录、@ 直通、自动接话、30 天整理）。
- Host 接线：`plugin-src/host/group-brain-runtime.mjs`（统一群聊会话生成器 + 每机器人 brain 注册表；记忆整理走一次性会话）、`group-brain-sessions.mjs`（每群 DSH 会话登记表 `<DSH_HOME>/integrations/dsh-im/group-brain/sessions.json`）、`group-brain-rpc.mjs`（并入 `/dsh-im-settings`）、`plugin-src/host/channels/qq/production.mjs`（创建 brain、主动发送走 `sendProactiveText`）。
- QQ 桥接：`src/channels/qq/qq-bridge.mjs` 在未 @ 判定与 `#process` 之前 `observe()`；@ 消息把群聊块追加到用户正文末尾（避免破坏 `injected-context.mjs` 的前导块解析）。
- 人设：`persona-presets.mjs` 新增独立 builtin `dafeiyu-group`（「大肥鱼（群聊版）」），原 `dafeiyu` 不改；选中私聊版时群聊回复额外叠加群聊准则。
- 设置页：通用页签新增「群聊大脑」区块（开关、白名单、接话节奏、连续对话窗口、记忆与画像参数、运行状态、立即整理）。被 @ 后默认开启 5 分钟连续对话窗口（最长可调至 30 分钟；窗口内默认最多续聊 8 条、可调至 100 条、最小间隔 3 秒），让一次 @ 可以自然延展成连续聊天；同群多个成员同时发言时按到达顺序排队逐一回复（同一成员连续消息默认 30 秒合并窗口内合并、窗口可调 0–120 秒、@ 优先）。
- 安全默认：自动接话只对白名单群或已知 ≤5 人群生效；另有冷却、每小时/每日上限；QQ 群拿不到成员数，因此必须配置白名单。
- 提示词最小化：`GroupBrain` 与微信个人号桥接都支持 `sessionExists` 回调——同一群首次回复完整注入人设/记忆/画像，之后复用同一 DSH 会话时只补最近消息与指令块（自动接话最近 10 条、@ 直通最多 8 条），避免每轮重复支付大段 token；完整内容仍以本地消息/`memory.md`/`profiles.json` 与会话历史为准。
- 微信个人号桥接（agent-wechat，实验性）：`src/channels/wechat-personal/agent-wechat-client.mjs`（daemon HTTP/SSE 客户端：health、accounts、threads、messages、groups、members、sends、events stream）、`wechat-personal-brain.mjs`（SSE 事件 → `GroupBrain.observe`；@ 直通 → 该群统一会话生成 → `POST /sends` 真实 @；自动接话 → `sendAmbient`；游标持久化、断线重连）、`plugin-src/host/wechat-personal-runtime.mjs`（按 `wechatPersonal` 配置启停单例、token 读取、人设解析、闲时门控、状态/连接测试）、`group-brain-rpc.mjs` 新增 test/personas 端点、设置页新增「微信个人号」区块。
- 微信个人号识图（暂缓）：图片识图能力暂时下线，`agent-wechat-client.mjs` 的媒体下载方法（`listMessageMedia` / `startMediaTransfer` / `getJob` / `downloadMessageImage`）与桥接侧图片输入均已注释保留为 TODO，恢复时启用即可；当前图片/文件/语音消息被忽略。
- 回复触发连续对话：机器人主动发言（自动接话/连续对话回复）后，群成员引用或回复它的消息会打开同一个连续对话窗口并直接回应（微信个人号通过 `quote.direction==='outgoing' && quote.senderId===ownUserId` 判定）；没人回复则窗口到期回到静默。
- 语音回复（可选，v5.10.0-personal.17）：微信个人号群聊可把模型回复朗读为微信语音条。推荐网关 `tools/song2cute/voice_hub.py`（voice-hub）：feiyu 兼容的 `POST /v1/speech`（内部代理 GPT-SoVITS 9850 `/tts`）→ 轮询 job → 下载 WAV；插件侧 `feiyu-voice-client.mjs` 作为客户端（Bearer Key 从文件读取）；`agent-wechat-client.mjs` 增加 `uploadMedia`/`sendVoice`/`sendFile`；桥接层支持两种语音模式——`标签触发`（识别 `<dsh_im_voice>…</dsh_im_voice>`，先发语音条、剩余文字照发）与 `始终语音`（每条普通回复先发语音条，长文本按 180 字/最多 4 段拆分，失败自动回退文字），@ 直通带提及、自动接话不带；设置页「微信个人号」区块新增语音子区块（开关/服务地址/Key 路径/模式/声线/字数/测试），RPC 增加 `settings.group-brain.wechat-personal.voice.test`；默认关闭，需要外部 GPU 声音服务，详见 [语音回复与 B 站翻唱](语音回复.md)。
- B 站翻唱接线（可选，v5.10.0-personal.17）：群成员「引用任意消息 → 发送 B 站视频链接 + 翻唱关键词 + 要求提示词」即可触发。`cover-command.mjs` 解析 URL/提示词/是否混音（提示词含「混音/带伴奏」才混音，默认纯人声）；`cover-service-client.mjs` 提交 voice-hub `POST /v1/cover`（内部调用 song2cute/B 站提取/TTL 临时文件）→ 轮询 → 下载音频（≤96MB）；结果以文件形式发回群并附说明文字，失败发文字提示；设置页「B 站翻唱（voice-hub）」子区块可配置开关/服务地址/Key 路径/提示词上限，RPC 增加 `settings.group-brain.wechat-personal.cover.test`；语音与翻唱共享同一把 voice-hub Key，需先部署 GPU 声音服务。
- 微信个人号验证结果：小号扫码登录成功（ownUsername `wxid_q7a7y4omt72222`），群「👫」`19129875381@chatroom` 可读消息与 5 名成员，真实 @ 元数据（`mentions.self=true`）可识别；实测入站 @ → 群脑 → 生成 → `POST /sends` 带 `mentions.userIds` 的真实群回复全链路通过。
- 回复排队与去重：每个群独立 FIFO 回复队列（最多 100 条），@ 消息优先、同一成员连续消息合并、生成期间继续接收 SSE 事件；`GroupBrain.observe` 对 duplicate 消息不再触发接话；桥接按游标与 messageId 跳过重复/重放事件；HMR 重载通过 globalThis 桥接注册表停掉旧实例，避免多个 SSE 连接重复消费。
- 统一群聊会话：同一群的 @ 回复、连续对话、自动接话复用同一个 DSH 会话（标题「群聊 · 群名」），登记表持久化；会话被删除/归档后自动重建；记忆整理仍是一次性会话。测试见 `test/group-brain-runtime.test.mjs`。
- 平台限制与风险：官方 iLink 微信机器人无法进普通微信群且平台不投递群事件，因此改用非官方 agent-wechat 协议（需常驻本机 daemon、专用小号，存在风控/封号风险；目前只处理文本消息与可选语音回复（需外部 GPU 声音服务），识图暂缓，文件暂不支持）。

使用说明见 [群聊大脑](群聊大脑.md)。

## 7. 构建、安装与验收

前置：Node >= 22.19、本机 DSH >= 0.2.1-rc.2（宿主验证基线 0.2.2-rc.1）。

```sh
cd dsh-im-persona
npm install          # 依赖已按微信/QQ 收敛
npm run build        # 生成 lib/index.js（Host）与 lib/client.js（Web 客户端）
npm test             # node:test 单测
npm run verify:trim  # 渠道裁剪静态扫描
node scripts/verify-package.mjs   # 发布包内容断言
```

安装到本机 Web profile（三选一）：

```sh
# 1) 本地链接安装（开发期推荐）
dsh plugin --profile web add -w link:/mnt/volume/dsh/dsh-im-persona

# 2) 个人版安装器
node bin/dsh-im-persona.mjs install --source .

# 3) 发布到 npm / GitHub 后
dsh-im-persona install --source github:GASNOOVA/dsh-im-persona
```

安装后重启 `dsh web`、刷新浏览器，打开「设置 → IM机器人」。

## 8. 风险、取舍与后续可选项

**风险**

1. 裁剪涉及大量交叉引用（i18n 聚合、RPC 列表、投递服务渠道枚举、测试 fixture），漏改会在构建期或运行期暴露；已用静态扫描脚本兜底，构建期会再次暴露。
2. 上游 `5.10.0` 与 DSH `0.2.1-rc.2` 绑定验证；本机 `0.2.2-rc.1` 需实测，若 Host API 有破坏性变化，需要少量适配（打包与导入层最容易出问题）。
3. 人设注入属于用户消息内容，模型可能不完全遵守；通过提示词约束与示例强化，不承诺"绝对人设"。
4. 个人版不再合并上游修复，安全问题（如凭据处理、平台协议变更）需要人工跟踪。
5. 认证投递契约（`describeBot` / `sendChecked` / `replyChecked` / `consumeInbound` / `historyChecked`）是上游飞书/Lark 专属实现，个人版渠道未实现对应能力，调用会返回 `capability-unavailable`；其中 receipt 校验仍引用飞书路由字段 `chatId`，属**随飞书删除后的死路径**（测试已 skip），后续可整体移除该契约。
6. 测试基线中仍有少量依赖 `~/.dsh` 可写权限或旧 `lib/` 产物的用例，在沙箱内可能因环境限制失败，已由测试记录区分。

**后续可选项**（按价值排序）

1. 人设预设库 + `/persona` 命令：多套人设一键切换，按聊天维度临时覆盖；
2. 人设注入升级为 Host `systemPrompt` 贡献（真正的系统级人格）；
3. 默认访问策略个人化：新机器人默认仅本人可用，而不是"所有用户"；
4. 彻底品牌化：内部 RPC 路由、数据目录、`plugin:dsh-im` 来源字段一并改名（需数据迁移脚本）；
5. 单人使用精简：多机器人管理 UI 可折叠/隐藏，设置页更扁平；
6. 个人 Logo 与截图：替换 `assets/` 占位图标，README 补个人界面截图；
7. 恢复 CI：GitHub Actions 跑 `npm run check`（本次未带入上游 CI）。
