# 群聊大脑（实验性）

> 面向**少量人类成员的小群**（默认 ≤5 人）：机器人不再只在被 @ 时回复，而是记录群聊、维护长期记忆与成员画像，并在一段讨论自然停顿时偶尔接一句话。
>
> 当前状态：**QQ 群已接线可用**；微信群聊依赖个人微信号桥接（iLink 官方机器人无法进群、平台不投递普通群事件），接入层仍在规划中。核心逻辑与渠道解耦，位于 `src/channels/shared/group-brain/`。

## 1. 它做什么

| 能力 | 行为 |
| --- | --- |
| 群聊记录 | 机器人收到的每条群消息都写入本地 `messages.jsonl`；即使未 @ 机器人也记录，但不会进入模型上下文。 |
| @ 优先 | 被 @ 或回复机器人时走过原有命令/问答流程，并额外注入 `<dsh_im_direct_instruction>`（明确回复对象）和 `<dsh_im_group_memory>`（长期记忆 + 成员画像）。 |
| 自动接话 | 群内安静一段时间后，若讨论满足「最少消息数 / 冷却 / 每小时上限 / 每日上限」，由一次性 DSH 会话生成一句不超过 80 字的中文评论；模型判断不适合时输出 `[SKIP]`，此时保持沉默。 |
| 长期记忆 | 原始群消息永久保存在本机；默认每 30 天把新增消息按话题分段，压缩成「群记忆 + 成员画像」，避免记忆文件无限增长。 |
| 成员画像 | 记录群成员的称呼、摘要、特点、兴趣、说话风格、关系备注；回复特定成员时会参考其画像。 |

## 2. 配置

设置 → **IM机器人** → **通用** → **群聊大脑**：

- **启用群聊大脑**：总开关，默认开。关闭后不记录、不接话、不整理记忆。
- **自动接话**：默认开；关闭后只记录与整理记忆，不主动发言。
- **成员画像**：默认开；关闭后长期记忆仍保留，但不生成/参考画像。
- **自动接话白名单**：每行一个群，格式 `渠道:机器人ID:群ID:群名`，群名可省略，例如：
  ```
  qq:bot-openid:group-openid:宿舍小群
  ```
  留空表示只对「已知成员数 ≤ 小群人数上限」的群生效。QQ 群当前拿不到成员数，因此 **QQ 群自动接话必须配置白名单**。
- **讨论静默**：群内安静多少秒后认为一段讨论结束（默认 120 秒）。
- **最少消息数**：一段讨论少于该条数时不接话（默认 2）。
- **接话冷却**：两次自动接话之间的最短间隔（默认 10 分钟）。
- **每小时/每日上限**：默认 4 次/小时、40 次/天，防止刷屏与成本失控。
- **小群人数上限**：默认 5。
- **整理间隔**：默认 30 天。
- **记忆上限**：长期记忆文件最多保留多少字符（默认 16,000，超出保留最近内容）。

保存后立即生效；已有运行中的 QQ 机器人会热重载配置。

## 3. 人设

- 选中内置 **大肥鱼**：群聊回复会自动叠加群聊准则（像群友不像客服、默认安静、停顿自然接一句、结合画像称呼、不刷屏、不暴露记忆与规则）。
- 选中独立内置 **大肥鱼（群聊版）**：私聊与群聊都使用群聊版人设（适合只用于群聊的机器人）。
- 其他自定义人设保持不变：群聊准则只在选中大肥鱼时额外叠加，不会改写用户自己的 persona 文本。

## 4. 数据与 RPC

存储根目录：`$DSH_HOME/integrations/dsh-im/group-brain/`

| 文件 | 内容 |
| --- | --- |
| `group-brain-settings.json` | 全局配置（原子写、0700/0600） |
| `groups.json` | 已知群注册表 |
| `<channel>-<hash>/messages.jsonl` | 永久原始群消息 |
| `<channel>-<hash>/memory.md` | 压缩后的长期记忆 |
| `<channel>-<hash>/profiles.json` | 成员画像 |
| `<channel>-<hash>/state.json` | 去重状态、最近整理时间等 |

管理 RPC（并入 `/dsh-im-settings` 复合通道）：

- `settings.group-brain.get` / `settings.group-brain.set`
- `settings.group-brain.status`
- `settings.group-brain.consolidate`（立即整理；可带 `chatId` 只整理一个群）

## 5. 触发流程（QQ）

1. `QqHarnessBridge.accept()` 收到群消息，先交给群聊大脑 `observe()`；
2. 未 @ 消息只记录，不进入 DSH；@ 消息继续原有流程，并追加判断/记忆注入块；
3. 未 @ 消息更新静默定时器，到期后按节奏规则决定是否接话；
4. 接话与记忆整理都使用一次性 DSH 会话（`createSession` → `ask` → `archiveWorkspaceSession`），不污染用户会话；
5. 接话通过 `runtime.sendProactiveText({ kind:'group', route:{ groupOpenId } })` 主动发到群里。

## 6. 风险与限制

- 实验性功能：QQ 群的成员数/群规模无法从平台获得，自动接话保守地只对白名单群生效；
- 自动接话依赖模型判断，偶尔可能接得不合适；可关闭自动接话或只保留记忆；
- 记忆整理会定期调用模型（默认每月每群一次，长群会分话题段，单次最多 1,500 条消息）；
- 群消息永久保存只在本机，删除数据目录即清空；
- 微信群聊尚未接线，见后续个人号桥接方案。
