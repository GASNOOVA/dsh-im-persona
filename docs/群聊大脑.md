# 群聊大脑（实验性）

> 面向**少量人类成员的小群**（默认 ≤5 人）：机器人不再只在被 @ 时回复，而是记录群聊、维护长期记忆与成员画像，并在一段讨论自然停顿时偶尔接一句话。
>
> 当前状态：**QQ 群已接线可用**；**微信群聊**通过可选的 agent-wechat 个人号桥接接入（实验性：iLink 官方机器人无法进群、平台不投递普通群事件，故使用本机 daemon 登录专用小号）。核心逻辑与渠道解耦，位于 `src/channels/shared/group-brain/`，桥接层位于 `src/channels/wechat-personal/`。

## 1. 它做什么

| 能力 | 行为 |
| --- | --- |
| 群聊记录 | 机器人收到的每条群消息都写入本地 `messages.jsonl`；即使未 @ 机器人也记录，但不会进入模型上下文。 |
| @ 优先 | 被 @ 或回复机器人时走过原有命令/问答流程，并额外注入 `<dsh_im_direct_instruction>`（明确回复对象）和 `<dsh_im_group_memory>`（长期记忆 + 成员画像）。 |
| 自动接话 | 群内安静一段时间后，若讨论满足「最少消息数 / 冷却 / 每小时上限 / 每日上限」，由该群固定的 DSH 会话生成一句不超过 80 字的中文评论；模型判断不适合时输出 `[SKIP]`，此时保持沉默。 |
| 统一会话 | 同一个群的 @ 回复、连续对话、自动接话全部复用同一个 DSH 会话（标题形如「群聊 · 群名」），模型能看到自己之前的发言，上下文连贯；会话被删除/归档时自动重建。记忆整理仍使用一次性会话，不占用群聊上下文。 |
| 提示词最小化 | 同一群第一次回复才完整注入人设、长期记忆与成员画像；之后复用同一 DSH 会话时只补充「最近几条消息 / 新的 @ 请求 + 指令块」，不再重复发送大段人设/记忆/画像，显著减少每轮 token 消耗。完整内容仍保存在本地群聊档案与会话历史中，功能不缺失。 |
| 连续对话窗口 | 被 @ 触发一次回复后，接下来一段时间内（默认 5 分钟）未 @ 的群消息也会直接自然接话，形成连续聊天；窗口内续聊有次数上限（默认 8 条，可在设置中调到 100 条）与最小间隔（默认 3 秒），避免刷屏。 |
| 多成员排队 | 同群多个成员同时说话时，回复按到达顺序排队、逐一回复；同一成员连续多条消息会在「同成员合并窗口」（默认 30 秒，可调 0–120 秒，0 表示立即回复）内合并成一次回复；@ 消息优先于普通续聊。每群最多排队 100 条，超出时丢弃最旧的普通续聊。 |
| 长期记忆 | 原始群消息永久保存在本机；默认每 30 天把新增消息按话题分段，压缩成「群记忆 + 成员画像」，避免记忆文件无限增长。 |
| 成员画像 | 记录群成员的称呼、摘要、特点、兴趣、说话风格、关系备注；回复特定成员时会参考其画像。 |
| 微信个人号群聊 | 可选接入 agent-wechat daemon；群消息经 SSE 事件流进入同一套群脑，@ 回复与自动接话都通过真实微信发送。 |

## 2. 配置

设置 → **IM机器人** → **通用** → **群聊大脑**：

- **启用群聊大脑**：总开关，默认开。关闭后不记录、不接话、不整理记忆。
- **自动接话**：默认开；关闭后只记录与整理记忆，不主动发言。
- **成员画像**：默认开；关闭后长期记忆仍保留，但不生成/参考画像。
- **自动接话白名单**：每行一个群，格式 `渠道:机器人ID:群ID:群名`，群名可省略，例如：
  ```
  qq:bot-openid:group-openid:宿舍小群
  ```
  留空表示只对「已知成员数 ≤ 小群人数上限」的群生效。QQ 群当前拿不到成员数，因此 **QQ 群自动接话必须配置白名单**。
- **讨论静默**：群内安静多少秒后认为一段讨论结束（默认 120 秒）。
- **最少消息数**：一段讨论少于该条数时不接话（默认 2）。
- **接话冷却**：两次自动接话之间的最短间隔（默认 10 分钟）。
- **每小时/每日上限**：默认 4 次/小时、40 次/天，防止刷屏与成本失控。
- **连续对话窗口**：被 @ 后多长时间内允许「未 @ 也直接接话」（默认 300 秒，0 关闭）。窗口从 @ 消息开始计算，不会因后续消息延长。
- **窗口内续聊上限**：一次 @ 引发的连续对话最多续聊几条（默认 8，最大 100，0 关闭）。
- **续聊最小间隔**：连续对话中最快多久回一句（默认 3 秒，避免连续刷屏）。
- **同成员合并窗口**：同一成员在这段时间内的连续消息合并成一次回复（默认 30 秒，可调 0–120 秒，0 表示收到就回复）。
- **回复排队**：自动生效。同群多个成员同时发言时逐条排队回复；同一成员的连续消息在合并窗口内合并为一次回复（默认 30 秒，可在面板调整）；每条消息只处理一次（重复/重放事件按游标与 messageId 跳过）。
- **小群人数上限**：默认 5。
- **整理间隔**：默认 30 天。
- **记忆上限**：长期记忆文件最多保留多少字符（默认 16,000，超出保留最近内容）。

保存后立即生效；已有运行中的 QQ 机器人会热重载配置。

### 微信个人号（agent-wechat）

同一面板的「微信个人号（agent-wechat）」区块：

- **启用**：打开后 Host 会连接本机 daemon 的事件流（默认 `http://127.0.0.1:16174`）。
- **daemon 地址 / 账号 ID / token 文件路径**：账号 ID 是 `wx accounts create` 时起的名字（如 `xiaohao`）；token 文件是 agent-wechat 数据目录下的 `api-token`。
- **群聊人设**：默认「大肥鱼（群聊版）」；也可选其他人设库条目。
- **测试 daemon 连接**：返回登录态、可见会话数与群列表，用来快速排查扫码/daemon 未启动问题。
- 自动接话规则与 QQ 共用；白名单格式 `wechat-personal:<账号ID>:<群ID>:<群名>`，例如
  ```
  wechat-personal:xiaohao:19129875381@chatroom:👫
  ```
  agent-wechat 能提供成员数，因此 ≤ 小群人数上限的群即使不配白名单也可自动接话（仍建议显式白名单）。

前置步骤：

1. `npm install -g @agent-wechat/cli`（Node >= 24；本机无需 Rust/Docker，安装包自带预编译大二进制）；
2. `wx accounts create xiaohao --alias xiaohao`；
3. `wx serve --listen 127.0.0.1:16174`；
4. `wx auth login --strategy qr`，用小号扫码并确认，`wx auth status` 应为 `authenticated: true` / `connection: online`；
5. token 位于 daemon 的 `--data-dir` 下的 `api-token`，把它填入插件设置。

注意：agent-wechat 是**非官方**微信协议实现，存在账号风控风险；请使用专用小号。

## 3. 人设

- 选中内置 **大肥鱼**：群聊回复会自动叠加群聊准则（像群友不像客服、默认安静、停顿自然接一句、结合画像称呼、不刷屏、不暴露记忆与规则）。
- 选中独立内置 **大肥鱼（群聊版）**：私聊与群聊都使用群聊版人设（适合只用于群聊的机器人）。
- 其他自定义人设保持不变：群聊准则只在选中大肥鱼时额外叠加，不会改写用户自己的 persona 文本。

## 4. 数据与 RPC

存储根目录：`$DSH_HOME/integrations/dsh-im/group-brain/`

| 文件 | 内容 |
| --- | --- |
| `group-brain-settings.json` | 全局配置（原子写、0700/0600） |
| `groups.json` | 已知群注册表 |
| `<channel>-<hash>/messages.jsonl` | 永久原始群消息 |
| `<channel>-<hash>/memory.md` | 压缩后的长期记忆 |
| `<channel>-<hash>/profiles.json` | 成员画像 |
| `<channel>-<hash>/state.json` | 去重状态、最近整理时间等 |

管理 RPC（并入 `/dsh-im-settings` 复合通道）：

- `settings.group-brain.get` / `settings.group-brain.set`（含 `wechatPersonal` 配置）
- `settings.group-brain.status`（含群脑与微信个人号运行状态）
- `settings.group-brain.consolidate`（立即整理；可带 `chatId` 只整理一个群）
- `settings.group-brain.wechat-personal.test`（测试 daemon 连接与登录态）
- `settings.group-brain.wechat-personal.personas`（可选的群聊人设列表）

微信个人号事件游标保存在 `$DSH_HOME/integrations/dsh-im/wechat-personal/cursor-<账号ID>.json`，断线重连从上次游标续传；首次启动（还没有游标文件）时从 daemon 当前游标开始，不回放历史群消息。

### 提示词与上下文复用

群聊回复不是每次把全部资料重新拼进提示词，而是按「会话是否已存在」分两种模式：

- **首次回复（新会话）**：完整注入群聊版人设、长期记忆、成员画像、最近对话/新消息与对应指令块；
- **后续回复（复用同一 DSH 会话）**：只注入本次新到的消息（@ 直通回复会带上 `<dsh_im_direct_instruction>`，自动接话只带最近 10 条对话），人设/长期记忆/成员画像不再重复发送——它们已经存在于该会话的历史里；
- 完整原始消息、`memory.md`、`profiles.json` 仍永久保存在本机数据目录，由 30 天整理任务维护，不依赖提示词常驻；
- 该优化不依赖外部记忆插件（如 Mnemon）：需要跨群/跨机器人共享记忆时，可后续把 `memory.md`/画像导出到记忆空间，但当前版本保持本地文件即事实来源。

## 5. 触发流程

### QQ

1. `QqHarnessBridge.accept()` 收到群消息，先交给群聊大脑 `observe()`；
2. 未 @ 消息只记录，不进入 DSH；@ 消息继续原有流程，并追加判断/记忆注入块；
3. 被 @ 后的连续对话窗口内，未 @ 消息直接触发自然接话；窗口外的未 @ 消息更新静默定时器，到期后按节奏规则决定是否接话；
4. 接话与 @ 回复复用该群固定的 DSH 会话（`createSession` 一次后反复 `ask`，见 `plugin-src/host/group-brain-sessions.mjs` 的登记表）；记忆整理仍用一次性会话；
5. 接话通过 `runtime.sendProactiveText({ kind:'group', route:{ groupOpenId } })` 主动发到群里。

### 微信个人号（agent-wechat）

1. `WechatPersonalGroupBridge` 连接 daemon 的 SSE 事件流（`/v1/accounts/<账号>/events/stream?after=<游标>`）；只处理群聊（`@chatroom`）的 `message.committed` 入站消息，先按消息 ID 取全文（正文在 `body` 字段）。
2. 消息经 `GroupBrain.observe()` 记录；@ 判断依据 `mentions.self`（真实 @ 元数据）或 mentions 列表包含机器人自身 `ownUsername`。
3. @ 消息：在该群固定的 DSH 会话里生成回复，通过 daemon `POST /sends` 发送并 `mentions.userIds` 真实 @ 对方；被 @ 后的连续对话窗口内，未 @ 消息也直接由桥生成自然回复（不 @ 人）；窗口外的未 @ 消息只记录，按静默/限流规则触发自动接话（`GroupBrain` 的 `send` → 桥的 `sendAmbient`）。
4. 生成前检查闲时启用（高峰时段自动 `[SKIP]`）；群名与成员数来自 daemon（群名缓存 60 秒），因此小群人数上限可自动生效。
5. 所有发送与接收消息都会写回群聊大脑的原始记录，长期记忆与画像来源与 QQ 完全一致。

## 6. 风险与限制

- 实验性功能：QQ 群的成员数/群规模无法从平台获得，自动接话保守地只对白名单群生效；
- 自动接话依赖模型判断，偶尔可能接得不合适；可关闭自动接话或只保留记忆；
- 记忆整理会定期调用模型（默认每月每群一次，长群会分话题段，单次最多 1,500 条消息）；
- 群消息永久保存只在本机，删除数据目录即清空；
- 微信个人号桥接使用非官方协议（agent-wechat），存在账号风控/封号风险，务必使用专用小号；daemon 必须常驻运行，目前只处理文本消息，图片/文件/语音留待后续；
- 同一 daemon + 账号只允许一个活跃桥接：插件热重载后会先停掉旧 SSE 连接再新建，避免重复消费同一条群消息；若 daemon 端口变化，请在设置里同步修改；
- 群消息按游标与 messageId 去重，重复/重放事件不会再次写入 `messages.jsonl`、也不会重复触发接话；
- agent-wechat 的 `@` 判断依赖平台真实 mentions 元数据；如果某个群消息没有 mentions（例如旧版客户端），可能被当作未 @ 消息处理；
- 统一会话会随群聊不断增长；billion-context 等宿主侧压缩插件会按会话折叠历史，若未安装此类插件、长时间高频群聊可能触及模型上下文上限。
- 统一会话登记表位于 `<DSH_HOME>/integrations/dsh-im/group-brain/sessions.json`；删除该文件后，下一次回复会为每个群新建会话。
